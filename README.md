# TAKE HIGH · прототип адмінки і сайту

Клікабельний прототип: адмінка і сайт зі спільними даними в Dropbox. Що змінили й зберегли в адмінці, зʼявляється на сайті за кілька секунд.

```
адмінка → Dropbox (файл take-high-data.json + фото) → сайт
```

- `admin/` — адмінка (HTML, CSS, JS без збірки і бібліотек)
- `site/` — сайт: Home за макетом «Homepage V2» і внутрішні сторінки в тому ж стилі (`site.css`, `js/site.js`, фото блоків Home у `site/img/`)
- `shared/` — початкові дані, фото вайрфрейму за ключами (`photos/`), мініатюри для адмінки, робота зі сховищем (`storage.js`)
- `tools/make-config.js` — створює `config.js` із секретів GitHub під час публікації
- `.github/workflows/pages.yml` — автоматична публікація на GitHub Pages

**Етап 1 з 4:** працюють вхід, Новини і Теги.
На сайті з адмінки беруться: блоки News і More from Media на Home, сторінка News (фільтри за розділом і тегом) і сторінка кожної новини.
Інші блоки Home поки зашиті в код і переходять в адмінку на етапах 2–3. Пункти меню, сторінок яких ще немає, ведуть до відповідного блоку на Home.

Адреси сайту: `site/#/` — Home, `site/#/news` — усі новини, `site/#/news?section=Media&tag=Film` — з фільтрами, `site/#/news/<адреса новини>` — новина. Стара адреса `#/latest` перекидає на `#/news`.

Тексти Home оновлено за правками копірайтингу. Невідомі дані лишаються заглушками в квадратних дужках, наприклад `since [year]`.

## Шрифт

У макеті використано Acumin — це платний шрифт Adobe. У відкритому репозиторії його не можна публікувати, тому сайт використовує близький безкоштовний Archivo (Google Fonts). Щоб показати сайт з Acumin: підключіть його через свій набір Adobe Fonts і додайте посилання на нього в `site/index.html`, або тримайте репозиторій приватним.

## Ключі доступу

У репозиторії ключів немає. `config.js` є в `.gitignore`. На GitHub Pages він створюється автоматично із секретів репозиторію.

Важливо: опублікований сайт працює в браузері, тому ключ Dropbox на ньому видно тому, хто відкриє інструменти розробника. Для прототипу це прийнятно, бо застосунок Dropbox має доступ лише до своєї окремої папки. Пароль адмінки зберігається тільки як SHA-256. Перевірка йде в браузері, тож це табличка «вхід лише для своїх», а не захист.

## 1. Застосунок Dropbox (≈5 хв)

1. Відкрийте https://www.dropbox.com/developers/apps → **Create app**.
2. Оберіть **Scoped access** → **App folder** → дайте назву, наприклад `take-high-prototype`.
3. На вкладці **Permissions** увімкніть `files.metadata.read`, `files.content.read`, `files.content.write`, `sharing.read`, `sharing.write` → **Submit**.
4. На вкладці **Settings** скопіюйте **App key** і **App secret**.
5. Отримайте refresh token. У браузері відкрийте адресу, підставивши свій App key:
   ```
   https://www.dropbox.com/oauth2/authorize?client_id=APP_KEY&response_type=code&token_access_type=offline
   ```
   Натисніть **Allow** і скопіюйте код. Потім у терміналі:
   ```
   curl https://api.dropboxapi.com/oauth2/token -d code=КОД -d grant_type=authorization_code -u APP_KEY:APP_SECRET
   ```
   У відповіді буде `refresh_token`.

Порядок важливий: дозволи (крок 3) треба зберегти **до** кроку 5. Якщо змінили дозволи пізніше, повторіть крок 5.

## 2. GitHub Pages (≈5 хв)

1. Створіть репозиторій і завантажте в нього всі файли з цієї папки.
   На безкоштовному тарифі Pages працює лише з публічним репозиторієм. Тоді тексти й фото вайрфрейму буде видно в репозиторії.
2. **Settings → Pages → Source: GitHub Actions**.
3. **Settings → Secrets and variables → Actions → New repository secret**, пʼять секретів:

   | Секрет | Що вписати |
   | --- | --- |
   | `DROPBOX_APP_KEY` | App key |
   | `DROPBOX_APP_SECRET` | App secret |
   | `DROPBOX_REFRESH_TOKEN` | refresh_token із кроку 5 |
   | `ADMIN_USER` | логін для входу в адмінку |
   | `ADMIN_PASSWORD` | пароль для входу в адмінку |

4. **Actions → Публікація на GitHub Pages → Run workflow** (або будь-який push у `main`). Через хвилину-дві на вкладці Actions зʼявиться посилання на сайт.

Під час першого входу адмінка створить у Dropbox файл даних `Apps/<назва застосунку>/take-high-data.json` із початковим контентом і перенесе в `Apps/<назва застосунку>/img/` фото, на які посилаються дані (≈50 файлів, близько хвилини; адмінка показує прогрес). Якщо перенесення перерветься, наступний вхід продовжить. Завантажені через адмінку фото теж лягають у `img/`.

## Запуск на своєму компʼютері

```
cp config.example.js config.js     # впишіть ключі або залиште test
python3 -m http.server 8000
```

Відкрийте http://localhost:8000/admin/ і http://localhost:8000/site/. Якщо замість ключів Dropbox стоїть `test`, дані зберігаються лише в цьому браузері. Так зручно пробувати без Dropbox. Вхід працює лише через `localhost` або https; з файлу без сервера (`file://`) він не працює.

## Як це працює

- **Збереження.** Адмінка завантажує файл даних, змінює потрібний запис і зберігає файл із перевіркою версії. Якщо файл тим часом змінили в іншому вікні, збереження не перезапише чужі правки і попросить оновити сторінку.
- **Оновлення сайту.** Сайт раз на 8 секунд перевіряє версію файлу в Dropbox і, якщо вона змінилася, перемальовується сам. В іншій вкладці того самого браузера зміни видно одразу.
- **Фото.** Перед завантаженням фото зменшуються до 1600 px. Для кожного фото Dropbox створює публічне посилання, яке записується в дані.
- **Журнал змін.** Кожне збереження пише запис у журнал. Екран журналу зʼявиться на етапі 3.

## Якщо щось не працює

- **«Dropbox не прийняв ключі доступу».** Перевірте три секрети Dropbox і що дозволи були збережені до отримання refresh token.
- **«Фото завантажено, але Dropbox не дав публічне посилання».** Увімкніть `sharing.write`, повторіть крок 5 і оновіть секрет.
- **Порожня сторінка або «Немає звʼязку з Dropbox».** Відкрийте консоль браузера (F12) і надішліть текст помилки.
